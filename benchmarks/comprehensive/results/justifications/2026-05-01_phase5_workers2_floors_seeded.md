# Phase 5.5 — workers2 floor seeding (DEADLOCK-ISSUE.md)

The two new `num_workers > 0` ml_loader metrics introduced in Phase 5.3
(`batches_per_sec__pyscx_training_dataset_workers2` and
`...workers2_persistent`) had no historical baseline because the path
deadlocked pre-Phase-2. Floors are seeded from a Lambda-HPC measurement
on 2026-05-01 (SLURM job `113074`, node `vci-steady-state-node-017`)
on a synthetic 100 000-cell × 2 000-gene fixture (≈ tabula_sapiens_100k
scale, generated by `benchmarks/scripts/lambda_phase5_workers2.py`):

| Scenario                                            | Median bps | Floor (0.5×) | Ratio vs `num_workers=0` (hvg_norm) |
|-----------------------------------------------------|-----------:|-------------:|------------------------------------:|
| `raw_workers0` (reference, num_workers=0)           |    2627.29 |          —   |                              1.000  |
| `hvg_norm_workers0` (reference, num_workers=0)      |    2722.12 |          —   |                              1.000  |
| `pyscx_training_dataset_workers2`                   |    1294.32 |        647.2 |                              0.475  |
| `pyscx_training_dataset_workers2_persistent`        |    1361.60 |        680.8 |                              0.500  |

The ~50 % efficiency vs `num_workers=0` is structural, not pathological:
the IterableDataset shim shards by batch index (`i % num_workers ==
worker_id`) so each cell is yielded once across workers, but each worker
still does the full I/O + decode pass over the file — paying 2× I/O for
1× output cells gives 0.5× aggregate throughput. The persistent variant
slightly outperforms the non-persistent because workers spin up once
across the run rather than per-epoch.

These floors will be re-baselined by a future canonical
`promote_baseline.py` run on the canonical hardware once the
Chimera-tuned `gate_candidate.py` orchestration is dispatched against
`tabula_sapiens_100k` and `census_1m`. Until then, the seeded floors at
0.5× the Lambda-measured median are conservative — any regression more
than 2× the observed throughput will trip the gate.

Re-measurement command:

```bash
sbatch benchmarks/scripts/lambda_phase5_workers2.sbatch
# Then:
python /tmp/apply_phase5_floors.py \
    --results benchmarks/comprehensive/results/phase5-lambda-workers2-<jobid>.json \
    --apply
```
