# AGENTS.md

## Project Overview

SCX (Sparse Cell eXpression System) is a purpose-built binary file format, compression codec, query engine, and ML data loader for single-cell RNA-seq data. It replaces AnnData/h5ad with a unified Rust-native stack: GPU-saturating training loader, lazy query engine, and Rust-native analysis accelerators. Native Python (`pyscx`) and R (`rscx`) bindings; compatible with scverse and Seurat v5. See [docs/performance.md](docs/performance.md) for benchmark results.

## Build and Test

```bash
# `--exclude rscx` matches CI: rscx pulls in extendr-api, whose build.rs panics
# without an R toolchain (it is a workspace member but not a default-member).
cargo test --workspace --exclude rscx
cargo clippy --workspace --exclude rscx --all-targets -- -D warnings
cargo fmt --check

# The line above runs at DEFAULT features, and nothing in the workspace enables
# `scx-convert/hdf5` by default — so it runs NONE of the h5ad/h5mu tests. Those
# need their own invocation (locally the simple additive commands below are fine;
# duplication with the default run doesn't matter on a dev box):
cargo test -p scx-convert --features hdf5
cargo test -p scx-cli --features hdf5 -- --test-threads=1
# CI's `Test (hdf5 features)` job runs only the hdf5-GATED subset instead — a
# --skip list of the 7 ungated scx-convert module prefixes plus `--test`
# selection of the 5 hdf5-gated scx-cli test binaries (see ci.yml; a dedup-guard
# step pins both lists to the crates' layout and enforces that hdf5-gated tests
# live in hdf5-gated homes).
# `--test-threads=1` is required, not tuning: the scx-cli hdf5 tests spawn the
# `scx` binary to open an h5ad the test process just created, and in parallel
# libhdf5 refuses the child's H5Fopen with `unable to lock file, errno = 11`.
# Measured on ext4 — it is cargo's parallel harness, not a network-filesystem
# quirk. The lock needs it only for the four binaries that link the hdf5 crate
# (CI serializes those plus doublet_import_hdf5, which rides along); every
# other scx-cli target never touches libhdf5.
# `HDF5_USE_FILE_LOCKING=FALSE` also works and is the convenient local escape on
# Weka/NFS/Lustre, but it hides real locking failures, so CI does not set it.

# With cloud features:
cargo test --workspace --exclude rscx --features cloud

# Python bindings (always use uv venv at .venv/):
cd pyscx && ../.venv/bin/maturin develop && ../.venv/bin/pytest tests/ -v

# Python bindings with cloud or GPU:
cd pyscx && ../.venv/bin/maturin develop --features hdf5,cloud,gpu && ../.venv/bin/pytest tests/ -v

# R bindings:
cd rscx && R CMD INSTALL .
```

**Always use the uv venv** at `.venv/` for all Python work. Do NOT use system Python or pip directly.

## Architecture (summary)

15 workspace crates plus two test-only ones (`scx-testkit` — the output-identity harness: `digest` for one file, `ab` for a labelled manifest of several, dumpable to JSON for a cross-worktree A/B — and the `scx-integration-tests` crate, whose `op_output_identity.rs` pins twelve arms over nine rewrite ops against a golden — `scx upgrade`, `subset`, multimodal compact/merge and the convert paths are **not** covered; the test's own "What this cannot see" section is the authoritative list); the dependency core is `{scx-codec, scx-sparse} → scx-format (pure on-disk layout/spec) → scx-format-io (runtime reader/writer/backed I/O) → {scx-mtx, scx-ops, scx-engine, scx-loader, scx-cloud, scx-gpu, scx-accel, scx-convert} → {scx-cli, pyscx, rscx}`. Full graph and isolation rules in [docs/architecture.md § Crate Dependency Graph](docs/architecture.md#crate-dependency-graph). Feature flags: `scx-cli{hdf5,hdf5-static,cloud,default-bin}`, `scx-convert{hdf5,hdf5-static}`, `pyscx{hdf5,hdf5-static,cloud,gpu}`, `scx-gpu{gds}`, `scx-accel{gpu}` — all opt-in.

File format ([docs/format.md](docs/format.md)): 256-byte LE header (magic `b"SCX\x01"`), 4096-byte root catalog at offset 256, 8-byte-aligned sections (29 types, IDs 0–29 with id 26 reserved), full catalog at EOF with per-entry checksums + shard statistics. v3 writers emit canonical row-major CSR. 76-byte CSR shard headers (magic `b"SCXS"`). Codecs: `None`, `Scx1` (integer only), `Pcodec` (float), `Zstd`, `Lz4Shuffle`, `ShufDeltaZstd`. The user-facing codec **intent axis** is `codec="auto"|"fast"|"compact"` (resolved by `scx_format::resolve_codec`): `auto` (default) is cost-aware adaptive — per framed integer shard it adopts `ShufDeltaZstd` when smaller by ≥ `ADOPT_MARGIN` (5%), else the heuristic (`Scx1` median ≤ 8, `Zstd` > 8); `fast` is the decode-max heuristic single-encode (the pre-flip default); `compact` adopts `ShufDeltaZstd` on ties. Float always → `Pcodec`. `auto` files are typically mixed-codec (`scx info` shows the per-shard breakdown). The prior `auto_v2` profile + `decode_target` knob were removed (pre-1.0 clean break). On-disk `u64`/`u16-u32`/`u8-u32`, in-memory `i64`/`i32`/`f32` to match scipy CSR zero-copy.

## Capabilities (summary)

- **Analysis accelerators** (`scx-accel`, [docs/scanpy.md § Rust-native accelerators](docs/scanpy.md#rust-native-accelerators)): PCA (CPU: covariance / randomized auto-routed by var count; GPU: rapids `rsc.pp.pca` for in-VRAM, native streaming/randomized for >VRAM), kNN (HNSW on CPU; rapids `rsc.pp.neighbors` on GPU), UMAP (rapids `rsc.tl.umap` on GPU), differential expression (pre-ranking Wilcoxon rank-sum; perturbation-screen `pdex_ref` matched to upstream pdex v0.2.x — MWU + pseudobulk log-fold-change with `epsilon` finite-guard default `1e-9`, `0/0 → 0.0`, and an optional `cpm_filter` per-gene CPM floor; `groups=` on both DE ops restricts the tested / reported groups, and `rank_genes_groups(pts=True)` writes scanpy's `pts` / `pts_rest` fraction-expressing frames via one route-independent counting pass — they round-trip through `from_anndata` / `to_anndata` and both h5ad directions on the `uns` `pandas.DataFrame` envelope; since 0.17 `rank_genes_groups` refuses **any** participating group with fewer than two cells in scanpy's words, whether or not `groups=` named it, and `reference="rest"` keeps unlabelled cells in the rank pool and in every group's "rest" as scanpy 1.12 does — a numerical change on partially labelled `obs` columns), Leiden (Rust-native CPU + cuGraph GPU), Harmony2 batch integration, LISI, HVG (streaming seurat_v3 / seurat; rapids `rsc.pp.highly_variable_genes` for extra GPU flavors), gene-set scoring (`score_genes`: CPU-native streaming `sc.tl.score_genes` equivalent + lighter `mean` / decoupler `zscore` methods; the `control` sampler is not numpy's, so it picks different control genes from scanpy and the scores differ by ~10 % of their range at the defaults — `ctrl_genes=` supplies the control set directly for exact parity, and works on a backed `X` where `sc.tl.score_genes` raises), PFlog (v4) / shifted-log normalization on raw counts (`pflog`: Booeshaghi et al., DOI 10.1101/2022.05.06.490859; matrix-wide Anscombe pseudocount `1/(4α)` with `α` estimated once via method-of-moments — `pflog(alpha=None)` estimates & stamps `uns["pflog"]`, a float pins a reference `α`; sparse `delta = log1p(4α·x)` + per-cell `baseline` decomposition → out-of-core baseline-aware PCA, in-memory dense layer, and streaming materialize-to-SCX in compact `delta_baseline` / literal `dense` reprs; also surfaced in the ML training loader and rscx), pseudobulk (aggregation + DESeq2-style Rust-native negative-binomial GLM DE — `accel.nb_glm` / `accel.pdex_nb_glm` / `pseudobulk_dex(backend="nb_glm")`, CPU-only, route `cpu_nb_glm`; **`nb_glm` is `pseudobulk_dex`'s default since v0.13** — it was `pydeseq2`, an optional dep no extra installed, so the default path raised on a base install; `backend="pydeseq2"` (the `pydeseq2` extra) is still there for exact DESeq2 numerics and is required by `stratify_by=` / `aggr_method="mean"`; see [docs/pseudobulk_nb_glm.md](docs/pseudobulk_nb_glm.md)), perturbation evaluation metrics (cell-eval / arc-bench parity). Since 0.18 `calculate_qc_metrics` runs **one** native kernel on every kind of `X` — backed, lazy, a backed layer handle, or an in-memory scipy/dense matrix — instead of delegating scipy/dense to scanpy; the two routes had written different obs/var column sets, and the delegation inherited scanpy's default `percent_top`, which raises on files with fewer than 500 genes. It gained `layer=` and a native `percent_top=` (computed in the existing row pass, default `None`), and it no longer needs the `scanpy` extra on any input. An **accelerator execution planner** (`scx_accel::route::plan_de_route`) decides and records the DE route + fallback reason on `adata.uns["scx_accel"][<op>]` (`route` ∈ `cpu_*`/`gpu_csr_v{1,2,3}`/`gpu_csc_v3`/`rapids_singlecell_gpu`/…); route-specific benchmark gates (`de_route_csc_direct`, `wilcoxon_route_gpu_correct`, `csc_dispatch_correct`, `hvg_route_gpu_correct`, `pca_route_gpu_correct`, `knn_route_gpu_correct`, `umap_route_gpu_correct`, `leiden_route_gpu_correct`, `*_route_rapids_correct`, `*_fallback_no_rapids_correct`) in `thresholds.yaml` turn silent GPU→CPU, CSC→CSR, or rapids→CPU dispatch fallbacks into hard gate failures across all GPU accelerator ops. See [docs/api.md § Accelerator route metadata](docs/api.md#accelerator-route-metadata).
- **GPU acceleration** (`scx-gpu`, `scx-accel`, [docs/gpu-setup.md](docs/gpu-setup.md)): `device="auto"|"cpu"|"gpu"|"gpu:N"` selector across `pyscx.accel.*`. In-VRAM ops route to **rapids-singlecell** when installed: PCA (`rsc.pp.pca`), kNN (`rsc.pp.neighbors`), UMAP (`rsc.tl.umap`), preprocessing (`rsc.pp.normalize_total`/`rsc.pp.log1p`), extra HVG flavors (`rsc.pp.highly_variable_genes`), and fused pipelines (`pca_neighbors`, `pca_neighbors_umap`). Native GPU paths survive for: streaming/randomized PCA (>VRAM moat), HVG `seurat_v3`, Leiden (Rust-native CPU + cuGraph GPU), DE Wilcoxon rank-sum/pdex (CSC/CSR-direct), Harmony, preprocessing kernels (ML loader + streaming), device-resident CAGRA kNN (fused path only), and codec decode (Rice/FOR-BP). `to_gpu_anndata()` provides minimal-copy on-device handoff (shard decode → device → `cupyx.sparse.csr_matrix`); Scx1 count shards — including dense ≥128-nnz rows via the BitPacker4x GPU kernel — decode fully in VRAM (`transfer_mode=scx_device_decode_gpu`, only the indptr uploaded), while non-Scx1 / sidecar-less shards host-bounce (`scx_device_handoff_streamed`). Rapids absent → CPU fallback with `FallbackReason::NoRapids` diagnostics. `SCX_FORCE_NATIVE_GPU=1` pins surviving native paths; `SCX_DISABLE_RAPIDS=1` forces CPU fallback for testing.
- **Lazy preprocessing**: `ScxLazyTransformedDataset` chains `normalize_total → log1p → row_scale` without materialization; `ShardSource` enables streaming PCA. Supports a full out-of-core pipeline (open → QC → normalize → log1p → HVG → PCA → kNN → UMAP → Leiden). See [docs/performance.md](docs/performance.md) for memory and throughput figures. A **row projection now skips the shards it empties** rather than decoding them to find them empty: the masked column kernels ask `BackedCsrIndex::shards_with_kept_rows` up front, and the streaming consumers (PCA, HVG, `score_genes`, `pflog`) get it from a defaulted `ShardSource::visible_shard_indices` the prefetch drivers consult — 5 → 1 shard decodes on a one-of-five-shard window. Row-axis kernels (`calculate_qc_metrics`' fused pass) are excluded by design; the streaming DE kernels were the last family running their own shard loop and now use the drivers too — Wilcoxon and pdex per gene chunk (so the skip is worth `n_gene_chunks x visited shards`), the `pts` counting pass once over the matrix, which also gave them the bounded decode-prefetch they lacked (a wall-clock claim of a shape [docs/benchmark_manifest.md](docs/benchmark_manifest.md) requires a manifest entry for, so it is not quoted). See [docs/sharding.md § Row-projected reads](docs/sharding.md#row-projected-reads-skip-whole-shards).
- **ML training loader**: Triple-buffered Rust pipeline (tokio I/O → rayon decode → Python consumer). Zero Python on the hot path, and no copy at the boundary for the bulk of a batch: `X`, the numeric obs columns and `cell_indices` are **moved** into numpy (`Vec::into_pyarray` adopts the allocation) on both the single-modality and the multimodal path — the multimodal builder used to clone, which on a 253-row multiome batch is ~183 MB per batch with the GIL held (a categorical obs column is the exception: its codes are decoded into a Python list, per batch). The shard indices the shuffler emits are positions in the selected modality's CSR shard list, and the ordering rule is a single primitive — `FullCatalog::csr_shard_indices`, which `csr_shards_sorted` / `csr_shards_for_modality` are also expressed in terms of — derived once per epoch in each of the two stages that need it rather than once per shard group; `ShardShuffler::shuffle_epoch_sorted` rejects a key list whose length disagrees with the shard count it was built for, and `MADV_WILLNEED` hints are issued inside `spawn_blocking` so the tokio reactor makes no blocking syscall. See `TrainingPipeline` in [docs/api.md](docs/api.md).
- **Read-side dtype / container materialization**: `to_anndata` / `PyQueryResult.to_anndata` / `to_csr` accept `container` (`"csr"`/`"dense"`), `data_dtype` (`float16/32/64`, `int8/16/32/64`, `uint8/16/32`), `index_dtype` (`int16/32/64`), and `allow_lossy`. The default (`csr`/`f32`/`i32`) is byte-identical and zero-copy. A non-default **eager** request narrows **in-decode**: `X` (and `adata.raw`) assemble directly at the target width via a typed reader (`scx_format_io::read_all_csr_shards_typed`/`_dense_typed` → `scx_sparse::{TypedCsr,TypedDense}`), never building the intermediate full-matrix f32 CSR — so a narrow `data_dtype=` **lowers** peak RSS (2 B/nnz for `uint16`, not 4 B/nnz + a narrow copy). Integer→integer narrows cast from the native `u32` stream (`scx_codec::CastFromU32` / `checked_cast_u32_into`), so a `>2²⁴` count read into `uint32`/`int64`/`float64` is **exact** (previously a hard error). Eager `layers` still cast post-assembly, and their decode-loss guard folds `value_max` over the **selected** layers only (`FullCatalog::layer_csr_max_value_over`, one pass over the catalog). Both that fold and `layer_csr_shards_named` — which sizes the projected path's parallel layer decode — resolve the per-modality *and* the legacy single-modality section naming through one predicate; matching only the former is a defect that has bitten twice, silently disabling rscx's `$layer()` guard (the name-scoped fold answered 0) and collapsing `decode_window` to 1 for every layer on a single-modality file. The **query** path decodes at the requested dtype when the dtype is declared before the decode — `to_anndata(obs_filter=…, data_dtype=…)`, or `query().collect(data_dtype=…)` (`scx_engine::QueryPipeline::collect_typed` → `TypedQueryResult`, which decodes each shard natively and narrows once, so a `>2²⁴` count through a query is exact; the same over cloud). A dtype named *after* a plain `collect()` is a cast of already-decoded f32 values and fails loud, naming `collect()`; `with_normalize`/`with_log1p` plus a non-f32 dtype is refused. `to_mudata` extends the same in-decode narrow **per modality** (`read_all_csr_shards_for_typed`): `container`/`data_dtype`/`index_dtype` each accept a scalar or a **dict keyed by modality name** (e.g. `data_dtype={"rna":"uint16","atac":"uint8"}`), each modality gated independently, unknown key → `ValueError`, dense not-yet-supported (CSR only). A fail-loud cast gate (`scx_codec::checked_cast_*` + dtype-aware `guard_decode_loss_for`, `allow_lossy=False`) rejects lossy narrowing (out-of-range, fractional→int, sign loss, count >2²⁴ into a target that can't hold it, e.g. `f32`/`f16`). `to_gpu_anndata` is f32-native and rejects the kwargs. See [docs/api.md § Container and dtype materialization](docs/api.md#container-and-dtype-materialization).
- **Handle staleness / lifecycle** (`scx-format-io/src/freshness.rs`, `pyscx/src/experiment.rs`): a `pyscx` handle that is asked to read a file which changed since it was opened **raises** instead of answering from its now-obsolete mapping. Covers `Experiment` and everything it hands out — backed `X` / layers / `obsm`, backed MuData, lazy mappings, `query()` pipelines. The check is opt-in per reader (`ScxReader::watching()`), so `scx-ops`, `scx-cli` and the ML training loader — which open readers around their own writes — are unaffected and pay nothing. Detection compares the file's inode (catches the copy-out ops, which rename a new file into place) and its header catalog pointer (catches the in-place ops and `rollback`); **timestamps are deliberately not used** — Linux updates inode times from a coarse clock, so a fast open→mutate sequence can land with an identical `st_mtime_ns`. `Experiment` gains `reload()`, `close()`, `closed` and context-manager support; `path` / `closed` / `close` / `reload` / `repr` never raise. Mutating *through* a handle (`pyscx.obs_import(exp, …)`, `exp.mark_deleted(…)`) reloads it. Cloud handles are out of scope. See [docs/api.md § Handles and files that change underneath them](docs/api.md#handles-and-files-that-change-underneath-them).
- **Optional dependencies and extras** (`pyscx/src/optional_deps.rs`): pyscx's hard deps are numpy / scipy / pyarrow / anndata (which brings pandas + h5py). Everything else — `scanpy`, `scikit-misc`, `pydeseq2`, `mudata`, `polars`, `formulaic` — is imported at the point of use through `import_optional(py, module, extra, op, dist)`, which raises a `ModuleNotFoundError` naming the op, the PyPI distribution and the exact `pip install 'pyscx[extra]'`. It rewrites **only** when the missing name is the requested top-level package; a failing submodule (`skmisc.loess` against a mismatched numpy) or a broken transitive dep propagates untouched, because "not installed" would be false and would bury the real diagnosis. Extras: `scanpy` (the accel ops that delegate to scanpy on an in-memory scipy/dense `X` — all of them are scanpy-free on a backed/lazy `X`), `hvg` (`scikit-misc`, for the default `highly_variable_genes(flavor="seurat_v3")` loess — needed on **every** `X` kind), `pydeseq2`, plus the pre-existing `mudata` / `10x` / `eval` / `nbglm` / `gpu` / `cloud` / `scvi` / `dev`. `pyscx/tests/test_optional_deps.py` blocks each module with a `sys.meta_path` finder and asserts both halves: the base-install surface works, and every other path names an extra that actually exists in `pyproject.toml`. See [docs/compatibility-matrix.md](docs/compatibility-matrix.md).
- **Multimodal**: CITE-seq / 10x Multiome / TEA-seq via the v2 format, including streaming h5mu ingest (`pyscx.from_h5mu` / `scx convert --from h5mu --stream` with `--modalities`/`--modality-types`) and multimodal `scx merge`/`compact`/`delete`/`subset --modality + --filter`. Deletion is whole-cell: the v2 deletion-vector format keys a global-obs-row bitmap by `modality_id` (`0` = every modality), so `mark_deleted` removes a cell from all modalities and a modality-scoped `query(modality=…)` returns deletion-filtered rows. (`scx append` on a multimodal target is deferred — rejected with `MultimodalUnsupported`; see Known Limitations.) See [docs/multimodal.md](docs/multimodal.md).
- **Streaming ingest** (`scx-convert/`): CSR / dense / CSC-on-disk h5ad and h5mu all stream into SCX with bounded peak RSS. `obsm` / `varm` / `obsp` / `varp` are hyperslab-read one row-range at a time and emitted as row-sharded sections (`<section>/<name>_shard_<idx>`, section types 20–23) so peak memory per metadata matrix matches one X shard; the pyscx backed-routing path detects per-section mutation via top-level h5py key comparison and routes clean sections through the disk streamer while still preserving in-Python edits to mutated ones. Obs metadata is emitted as row-sharded `ObsMetadataShard` sections under `--shard-obs off|auto|always` / `shard_obs=` (default `auto` = shard when `n_obs > shard_target_rows`), resolved by the shared `scx_format::ObsShardPolicy` and written by the shared `scx_format_io::write_obs_section`, so `scx convert` (h5ad/h5mu/10x/mtx), `from_anndata`, `compact --reshape-obs` and `optimize --shard-obs` all call one function and cannot drift; **var is never sharded on ingest**, and sharding obs does not change conversion peak RSS (obs is read whole and `RecordBatch::slice` is zero-copy) — what it buys is that converted files exercise the streaming h5ad export writer, which is otherwise reachable only from `from_anndata` output. CLI / pyscx kwargs: `--memory-budget`, `--strict-uns`, `--dense-zero-epsilon`, `--temp-dir`, `--shard-obs`, plus h5mu `--modalities`/`--modality-types`. Ingest and export options are **separate types** (`IngestOptions` / `ExportOptions`), so an export-only option cannot be set on an ingest call — the runtime helper that used to reject that combination at five entry points is gone. 1-D HDF5 **string** *datasets* on the ingest side have one decoder (`scx-convert/src/h5ad/strings.rs`): every flavour, one const-generic width ladder keyed on **bytes**, one HDF5 read, and a `StringSink` that decides the output shape — the sink is `GenericStringBuilder<i32>` (payload copied once, byte-identical `Utf8` output, no validity buffer where there was none), `MaskedUtf8Sink` for the `nullable-string-array` form, or `Vec<String>` for the five join-key / `serde_json` consumers that need owned strings. Two readers had hand-rolled that ladder and lost its fixed-width half, so a **PyTables-written** (CellRanger / CellBender) `categorical` or `nullable-string-array` obs column was silently dropped with a `SkippedColumn` warning; both now read. **Not every string read routes through it**: rank-0 (scalar) reads, `uns`'s fixed-width 1-D arm and attribute reads decode themselves — and the same fixed-width drift is still live on the `uns` scalar path, which needs `read_scalar` rather than `read_1d` and so needs a scalar companion to close it. Structured `ConvertWarning` channel; provenance entry records per-category counts. See [docs/api.md § Conversion warnings](docs/api.md#conversion-warnings-convertwarning) and [Memory budgets](docs/api.md#memory-budgets).
- **Parallel streaming reader (ingest)** (`scx-convert/src/pipeline/coordinator.rs::run_streaming_writer_coordinator`): h5ad CSR / dense / in-memory CSC ingest fans shard reads out across a rayon worker pool with a bounded crossbeam reorder buffer; output is byte-identical to the sequential path. Default `reader_threads = None` resolves to `RAYON_NUM_THREADS` or `available_parallelism()`. Gated by a runtime `H5is_library_threadsafe` probe — non-threadsafe libhdf5 (e.g. statically linked) falls back to the sequential coordinator with a one-shot `ConvertWarning::Hdf5NotThreadsafe`. `--memory-budget` derates worker count to fit a per-worker **whole-phase** cost — `shard_target_rows × n_vars × density × 48 B` for sparse readers, `shard_target_rows × n_vars × 44 B` for the dense reader (payload/slab, the encoder's value copy, and the framed encode's two concurrent candidates) — and refuses to start when a single shard exceeds the budget. The three per-shard rows in `budget.rs`'s allocation table are `enforced: true` because of that; the four remaining unenforced rows are all CSC. Every share and per-element cost is declared once in `scx-convert/src/budget.rs` (**the allocation table**), which states what fraction of a budget each phase may claim and unit-tests that the concurrent ones sum to ≤ 1; a CI guard rejects budget arithmetic written anywhere else. The dense figure does not scale with the source dtype width — the resident slab is f32 whatever the input was. CLI / pyscx kwargs: `--reader-threads`, `--writer-queue-depth`. CSC external-memory transpose and h5mu cross-modality stay sequential by design.
- **Streaming export** (`scx-convert/src/h5ad/stream_write.rs`): SCX → h5ad / h5mu via pre-allocated HDF5 hyperslab writes. CLI `scx convert --to h5ad/h5mu` and `pyscx.to_h5ad` / `pyscx.to_h5mu` stream by default; peak RSS bounded by one shard's worth of CSR per matrix written — `X`, every `layers` entry, and **`adata.raw`** (`stream_raw_at`, on raw's own wider gene axis from `raw_n_vars()`; `raw/var` stays whole-batch because var is never sharded). `obsm` / `varm` / `obsp` / `varp` are still read whole and are the remaining unbounded term (OPT-CONVERT-4). Sharded obs/var (`ObsMetadataShard` / `VarMetadataShard` sources) also stream via `write_dataframe_group_from_shards` in `h5ad/column_stream.rs` — pre-allocated HDF5 datasets per column, hyperslab writes per shard. That function is the **only** dataframe-column writer: `write_dataframe_group_at` is a whole-batch *driver* over it (an assembled frame is one shard), so the nine column encodings exist once. Categoricals intern each shard's **declared** vocabulary in declared order, so a `pd.Categorical`'s category list, its unused levels and its `ordered` bit all survive; a level no row uses is pruned only when a row filter is active (pandas' `remove_unused_categories()`-on-subset rule), decided by a second decode pass (`scan_used_categories`, `h5ad/columns.rs`) that runs *only* when a keep mask is present. Deletion vectors handled via a single-pass pre-scan so on-disk layout stays deterministic; the keep mask is passed *through* to the writer on both drivers rather than applied to the batch first (pre-filtering hides it from the writer — `arrow`'s `filter` keeps a `DictionaryArray`'s full dictionary). `--stream=false` / `stream=False` falls back to the legacy materialising path. An optional caller-supplied obs row filter — `obs_mask=` / `min_counts=` on `pyscx.to_h5ad`, `--min-counts` on `scx convert` — is **intersected** with (never substituted for) the deletion-vector keep mask, accepted in either obs row space — `n_obs_physical` entries, or the live `n_obs` entries `read_obs()` describes, expanded through the keep mask; a pandas Series' labelled index is checked for order, and requires the streaming path; a filtered export records what it dropped in `uns["scx_export"]`.
- **CellBender interop** (`scx-convert/src/cellbender.rs` + `scx-ops/src/external_layer.rs`): export a raw all-droplet file with a result-preserving low-UMI pre-trim (`to_h5ad(min_counts=…)`), run `cellbender remove-background` externally, then land its corrected counts as a layer with `pyscx.cellbender_import` / `scx cellbender-import`. The import is **in place** via `prepare_in_place`/`commit_in_place`, so X, the CSC sidecar, `.raw`, deletion vectors and predicate indexes survive and `scx rollback` undoes it; the join is by **barcode string, never row position** (CellBender's `_filtered.h5` is in descending-UMI order). `--dry-run` reports the join without writing. The write side, `scx_ops::attach_external_layer`, is generic — no CellBender knowledge. See [docs/operations.md § CellBender import](docs/operations.md#cellbender-import).
- **External obs import / doublet-caller interop** (`scx-ops/src/external_obs.rs` + `scx-convert/src/{annotation_table.rs,doublet.rs,h5ad_obs.rs}`): land any per-cell annotation computed outside SCX onto an existing file as `obs` columns — `pyscx.obs_import` / `scx obs-import` for a delimited table (**ungated**, no libhdf5) or an `.h5ad`'s `/obs` (`hdf5` feature), `rscx::scx_attach_obs` for an R `data.frame` straight off an rscx-loaded object. In place via `prepare_in_place`/`commit_in_place`, so X, layers, `var`, the CSC sidecar, `.raw`, deletion vectors and bitmaps survive and `scx rollback` undoes it; the join is **by key string, never row position**, and target rows the source does not cover get `null`, never a fabricated `0.0` (`on_missing_rows` defaults to `"null"` on every obs surface; `"zero"` is an accepted alias, and stays the default only on `cellbender_import`, where a missing *matrix* row genuinely is zeros). The two sides may name the key differently — `source_key=` / `--source-key` pairs source columns to `key=` components positionally, like pandas `left_on`/`right_on` — and `obs_names` names the obs index anywhere a key is accepted (the physical `__index_level_0__` field is never surfaced, since `read_obs()` returns it as the frame's unnamed index). Predicate indexes survive a pure column *add* (`obs_index_would_go_stale` decides precisely) and are dropped only when `overwrite` rewrites an indexed column. `pyscx.diagnose_obs_key` names the columns / two-column composites that are unique — load-bearing on a merged atlas, where the obs index often is not and the one unique column may be one no fallback list would guess; it reports only keys the join accepts, best-candidate-first (obs index → barcode-style names → strings → integers), with unique-but-refused columns such as float scores listed apart under `unusable_unique_columns`. On top sits the doublet wrapper: `pyscx.doublet_import` / `scx doublet-import --tool {scdblfinder,scrublet,doubletfinder,doubletdetection,solo,scds,generic}` normalises each caller's spellings onto `<K>_score` / `<K>_predicted` / `<K>_status` + `uns["<K>"]` (a score-only tool gets no `<K>_predicted` — thresholding is not the importer's decision); `pyscx.export_batches` writes one h5ad per batch with a two-identity within-batch key guard; `pyscx.doublet_consensus` combines N tools under `majority`/`any`/`all`/`mean_rank`, null-aware throughout (a tool that never saw a cell does not vote; a cell nobody voted on stays `null`). Gated end to end by the `doublet_interop` benchmark in `benchmarks/comprehensive/`. See [docs/operations.md § External obs import](docs/operations.md#external-obs-import) and [docs/scanpy.md § Landing external per-cell annotations](docs/scanpy.md#landing-external-per-cell-annotations-doublet-detection).
- **External var import** (`scx-ops/src/external_var.rs` + `scx-convert/src/annotation_table.rs`): the same seam on the gene axis — `pyscx.var_import` / `scx var-import` for a delimited table (**ungated**) or an `.h5ad`'s `/var` (`hdf5` feature), `pyscx.attach_var_columns` for an in-memory DataFrame, `rscx::scx_attach_var` for an R `data.frame`, `pyscx.diagnose_var_key` for the key reconnaissance. Key-joined by `var_names` (then `gene_id`/`gene_ids`/`id`/`feature_id`/`gene_name`/`gene_symbol`/`name`) with `positional=True` opt-in, in place, `scx rollback`-able, and it replaces `modify_metadata(var=<whole frame>)` for the add-one-column case. Three deliberate divergences from the obs twin: **the layout survives** (a sharded var is rewritten shard-by-shard with the same boundaries, a single section stays one — nothing on the ingest path creates var shards and the rewrite ops collapse them, so an attach is the wrong place to change a layout); a stale **var predicate index is rebuilt, not dropped** (one batch-mode build over `[(0, n_vars)]` with the new table already in memory — and there are no per-shard var column stats, so a var attach clears none, which a copy from the obs op would get wrong); and there is **no live/physical row-space dispatch**, deletion vectors being obs-only. A multimodal target is refused (each modality owns its own `var/<name>` section), as on `attach_external_layer`. The join internals are shared with the obs op rather than copied — `AxisJoinKey` (`ObsJoinKey` is a kept alias), `build_new_axis_batch`, `build_axis_row_join`, `index_would_go_stale`, `resolve_axis_key_column`, `build_composite_key_for`, `read_annotation_table_for`, `read_h5ad_axis` — which is what closed two long-standing `attach_external_layer` defects (a collapsed sharded var, an uncarried stale var index) and one on both source readers (a non-key index field imported as a column named `__index_level_0__`). Note that no query path reads the var predicate index today: `filter_var` evaluates against the assembled `var` batch. See [docs/operations.md § External var import](docs/operations.md#external-var-import).
- **Parallel streaming reader (export)** (`scx-convert/src/h5ad/stream_write.rs::stream_csr_to_group_at`): SCX → h5ad / h5mu shard decode + filter runs on a rayon worker pool; the HDF5 writer stays on the calling thread (libhdf5 holds its own global lock, but workers never touch HDF5 here). No `H5is_library_threadsafe` probe required and no density heuristic — per-shard memory comes from exact `FullCatalogEntry::stats.nnz` and row range. `pyscx.to_h5ad` / `pyscx.to_h5mu` accept `reader_threads=`, `writer_queue_depth=`, `memory_budget=` kwargs symmetric with `from_h5ad` / `from_h5mu`. Same rolling-window spawn cap as ingest (`reader_threads + writer_queue_depth`); same `ReaderThreadsDerated` warning when `memory_budget` shrinks the granted thread count.
- **Streaming SCX → SCX rewrite**: `pyscx.from_anndata(adata, out)` accepts `adata.X` as `ScxBackedSparseDataset` or `ScxLazyTransformedDataset` and streams shard-by-shard. Byte-passthrough fast path when source/target shard layouts agree (matching `shard_size`/`codec`, no deletions or column projection, single-modality source); decode-encode fallback otherwise. Lazy `X` always decode-encodes with transforms applied per shard. Provenance entry records `x_source` / `passthrough` / `lazy_transforms`. See [docs/api.md § `pyscx.from_anndata` — backed and lazy `X`](docs/api.md#pyscxfrom_anndata--backed-and-lazy-x).
- **Streaming merge / append** (`scx-ops/`): `pyscx.merge` and `scx merge` operate shard-by-shard at every level — obs metadata (via `ObsMetadataShard` / `VarMetadataShard` section types 24–25), X / layer CSR shards, and obsm / varm dense mapping shards are never fully materialized. Removes the previous Arrow IPC 2 GB narrow-offset ceiling on obs string columns. Var identity is validated by default (`assume_identical_var=False`); `UnsPolicy` controls conflict resolution (`first` / `require-equal` / `namespace` / `summary`). `pyscx.append` writes new obs as shards (existing obs is not rewritten). Predicate indexes are built incrementally from the obs shard stream. `pyscx.from_anndata` emits sharded obs/var when `n_obs > shard_target_rows`; `force_legacy_metadata=True` opts out. Obsm / varm / obsp / varp are extracted and written one key at a time. See [docs/scanpy.md § Merging datasets](docs/scanpy.md#merging-datasets) and [docs/sharding.md § Obs/var metadata sharding](docs/sharding.md#obsvar-metadata-sharding).
- **Query-ready conversion**: `scx convert --index-obs/--index-var/--index-preset {cellxgene,perturbseq,training}` materialises predicate indexes at write time so `pyscx.open(...).query()` and `scx pull --filter` (a `--features cloud` build only — see [docs/cloud.md § Enabling cloud support](docs/cloud.md#enabling-cloud-support)) push predicates down. The same `--index-*` flags exist on every derived-file op — `merge`, `compact`, `sort`, `append`, and `subset` — which **rebuild** the index against the output rather than carrying the input's over (row / column projection invalidates its shard ranges); omitting them leaves the output with no predicate-index sections and `filter_obs` falling back to a full obs scan. `--bitmap auto|always` writes per-shard gene→local-row roaring bitmap sidecars (`SCXB`, section id 6) consumed by `Experiment.detection_counts` / `cells_expressing`. See [docs/format.md § 12](docs/format.md#12-detection-bitmap-optional) for the wire format and the [Operations Matrix](docs/operations.md#operations-matrix) for the per-op in-place/copy-out split.
- **Cloud-native query**: `pyscx.open_cloud(url).query().filter_obs(...).select_genes(...).collect()` and `scx query <url-or-dir>` serve selective reads directly over `object_store` range reads without `scx pull`. Shared `SectionReader` trait unifies local mmap and cloud paths; `QueryPipeline::from_reader` is the seam. Sharded obs/var metadata (`ObsMetadataShard` / `VarMetadataShard`) is assembled on the cloud path via `CloudReader::read_obs`/`read_var` + the shared `scx_format_io::assemble_sharded_metadata` (parallel range reads), so atlas-scale files from streaming merge/append/from_anndata open over `open_cloud`; the single file-scope `ObsPredicateIndex` is read unchanged. Deferred follow-ons: `CloudQueryOptions`, `pyscx.read_cloud(...)` flat helper, batched async fetcher, and incremental per-shard predicate-index merge for stale-after-`append` indexes (today a stale file-scope index falls back to a full obs scan over appended rows). See [docs/cloud.md § Cloud-native query](docs/cloud.md#cloud-native-query).

## Coding Conventions

See **[docs/conventions.md](docs/conventions.md)** for the full ruleset. Highlights:

- **Tracked files MUST NOT reference gitignored markdown** (`tasks/*.md`, root scratch docs like `2026-*_REGRESSIONS.md`, `*_CODE-REVIEW.md`, `Phase*.md`). Inline the substance instead of citing.
- **Do NOT stage/commit all-caps markdown files in the repo root** (e.g., `MERGE-OBS-OFFSET-OVERFLOW.md`, `STATE-CELL-EVAL-INTEGRATE-PT2.md`). These are ephemeral implementation/planning documents that are moved to `./tasks/` after completion, and `./tasks/` is gitignored. Exceptions: `README.md`, `ROADMAP.md`, `AGENTS.md`, `CLAUDE.md`.
- **On-disk structs**: no `#[repr(C)]`; serialize field-by-field with `byteorder` little-endian; sections at 8-byte-aligned offsets.
- **Errors**: `thiserror` enums per crate; readers return errors (not panic) on malformed input.
- **Checksums**: BLAKE3 everywhere (truncated-64 per shard, full-256 for catalog).
- **Writer**: temp file → `fsync` → `rename`; sections start at offset 4352.
- **pyscx**: `Bound<'py, T>` API, `i64/i32/f32` matches scipy.
- **Tests**: small inline `#[cfg(test)] mod tests` is fine; extract large ones to a sibling `*_tests.rs` via `#[cfg(test)] #[path = "…_tests.rs"] mod tests;` (keeps white-box `super::*` access). See [docs/conventions.md](docs/conventions.md).

## Known Risks and Pitfalls

- **HDF5 crate (`hdf5-rust`)** is unmaintained; only needed for conversion. Fallback: Python subprocess with h5py.
- **h5ad files are messy** (missing encoding-type attrs, CSC instead of CSR, dense X, pickled uns) — handle gracefully.
- **tokio + rayon interaction** (`scx-loader`): tokio for I/O only, rayon for CPU; bounded channels for back-pressure.
- **Cloud auth**: `object_store` handles credentials via env vars and instance metadata; no custom auth code.
- **SLAF runner quirks** (extending `slaf_runner.py`): `SLAFArray.get_submatrix` treats integer selectors positionally and returns string `cell_id` / `gene_id` columns that are NOT unique across Lance fragments at census scale — the runner goes through the internal `expression(cell_integer_id, gene_integer_id, value)` SQL table instead. `get_submatrix` rejects numpy arrays. `SLAFDataLoader`'s Mixture-of-Scanners prefetcher returns 0 batches on Census 10M with the default config — upstream issue, not harness.
- **rapids-singlecell dependency**: detected at runtime, not a build dependency or pip extra. Requires conda install or GPU-node source build (CUDA-arch coupled). GPU analysis ops (PCA, kNN, UMAP, preprocess) fall back to CPU with `FallbackReason::NoRapids` diagnostics when absent. Install story in `docs/gpu-setup.md`.

## Known Limitations

- **GPU analysis strategy**: In-VRAM GPU analysis routes to rapids-singlecell (faster on all ops except Leiden); native GPU code retained only for streaming/out-of-VRAM paths, Leiden, DE, Harmony, and the ML loader. Routing details and current numbers: [benchmarks/README.md § GPU accelerator regression workflow](benchmarks/README.md#gpu-accelerator-regression-workflow); see [docs/performance.md](docs/performance.md) for per-op speedups.
- **GPU Leiden correctness**: label stability differs from Python `leidenalg` — documented behaviour of `device="gpu"` / `"auto"` on GPU hosts, not a regression. Pin `device="cpu"` to preserve label stability for downstream DE / annotation transfer.
- **Benchmark baseline scope**: capture and gate coverage differ. `LATEST` is the canonical baseline; prior baselines remain under `results/baselines/` for historical A/B. Justifications suppress both regression and absolute-floor violations on a triple. Deferred floors are catalogued in `benchmarks/comprehensive/thresholds.yaml` § "Deferred floors": SLAF `ml_loader` (separate conda env), `avg_gpu_util_pct__gpu_train` (needs in-process sampler), `census_1m × cell_eval_parity_perf` (cell-eval reference is O(N²)).
- **Catalog version auto-upgrade**: `FullCatalog::write_to` auto-upgrades `catalog_version` to ≥2 on serialise to match the v2 stats layout that `ShardStats::write_to` always emits. Closes the cloud-fixture symmetry bug class. Regression test `scx-format::catalog::tests::write_upgrades_v1_catalog_to_v2`.
- **Fixture refresh**: `benchmarks/scripts/reconvert_fixtures.py` is the canonical entry point when h5ad sources change; `gate_candidate.py --probe-cloud` catches missing/mismatched `gcsfs` and catalog-format bugs in <30 s.
- **CSC storage**: optional gene-major sidecar via a three-state `CscPolicy` (`scx_format::CscPolicy` = `off`/`auto`/`always`) on `pyscx.from_anndata(csc=...)` / `scx convert --csc=...` / `scx build-csc`; `auto` builds when `n_obs ≥ 50000` and `n_vars ≥ 5000` (env-tunable via `SCX_CSC_AUTO_OBS_THRESHOLD` / `SCX_CSC_AUTO_VARS_THRESHOLD`). Multi-shard layouts via `--csc-cols-per-shard`. On the CPU, consumers opt into the column-major path with `prefer_format="csc"` on supported `pyscx.accel.*` ops (PCA explicitly rejects CSC); this is the **CPU** path and has no GPU kernel (`prefer_format="csc"` + `device="gpu"` errors). GPU CSC-direct is selected by the planner, **not** by `prefer_format`: with the default `prefer_format="csr"` + `device="gpu"`/`"auto"`, GPU `pdex_ref` and `rank_genes_groups` take the `gpu_csc_v3` CSC-direct route automatically when a CSC sidecar is present — v3 is the default GPU DE route (the `SCX_GPU_DE_V2`/`SCX_GPU_DE_V3` opt-in gates were removed when v3 became the default); in-memory CSR (or no sidecar) falls back to `gpu_csr_v3` ("GPU-fast" requires a CSC sidecar — see [docs/scanpy.md § GPU-supported vs GPU-fast](docs/scanpy.md#gpu-supported-vs-gpu-fast)). Mutating ops drop the sidecar by default with a warning; `--rebuild-csc` to re-emit. See [docs/sharding.md § CSC sharding](docs/sharding.md#csc-sharding).
- **Multimodal limitations**: `scx merge`, `scx compact`, `scx delete` (`mark_deleted`), and `scx subset --modality NAME --filter/--genes` composition all shipped — `scx-ops::{merge_multimodal, compact_multimodal}` dispatch on multimodal inputs and `scx info` exposes a per-modality `has_csc` column. Multimodal `mark_deleted` is a whole-cell delete via the v2 deletion-vector format (global-obs-row bitmap keyed by `modality_id`, `0` = every modality), so the earlier engine guard that rejected modality-scoped queries on files with deletions is gone; per-modality *scoped* deletion (drop one modality's measurement) is reserved wire-format headroom, not yet exposed. **`scx append` / `pyscx.append` on a multimodal target is deferred** (rejected in `prepare_append` with `OpsError::MultimodalUnsupported`): a single-modality append bumps the global `n_obs` while extending only that modality, leaving siblings under-covering the cell-aligned obs axis → an unreadable file; extract a modality via `scx subset --modality`, append, then `scx merge` back. Modality-scoped predicate pushdown ships for **local and cloud**: `pyscx.open(...).query(modality="rna")`, `open_cloud(url).query(modality="rna")` / `read_cloud(url, modality="rna")`, `scx query [--modality rna]` (local or cloud URL), and rscx `scx_query(exp, modality="rna")` scope X / `select_genes` / `filter_var` to one modality while `filter_obs` evaluates against the shared global obs axis (`scx_engine::QueryPipeline::open_for_modality` / `from_reader_for_modality`; obs predicate is modality-independent because each modality's CSR shards independently tile `[0, n_obs)`). The cloud reader routes per-modality `var`/CSR sections over both packed and exploded `.scxd/` layouts. Other remaining limitations: cloud `open_cloud(...).to_mudata(backed=True)` (local backed multimodal works; cloud multimodal `query` works), and spatial transcriptomics with R-tree spatial index (separate spec).
- **GDS**: GPUDirect Storage requires local NVMe + nvidia-fs drivers + ext4/XFS; always falls back to the CPU path.
